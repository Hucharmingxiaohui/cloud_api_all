# 本地调试使用服务器地图

后端接口地址与地图服务地址独立。`public/config.js` 的 `baseURL` 指向 Java 后端；地图瓦片通常由独立的静态文件服务提供，不能直接套用后端的 6789 端口。

1. 将 `env/.env.development.local.example` 复制为 `env/.env.development.local`。
2. 在文件内填写 `DEV_MAP_TILE_TARGET=http://服务器IP:地图端口`。
3. 停止并重新运行 `npm run serve`，浏览器强制刷新，避免使用之前缓存的本地瓦片。

例如服务器瓦片地址为 `http://服务器:19922/18/206473/112458.png`，填写 `http://服务器:19922`；如果服务器页面使用 `http://服务器:9921/api/18/206473/112458.png`，填写 `http://服务器:9921/api`。不要填写完整瓦片文件名。

配置后，浏览器仍请求本地 `/api/{z}/{x}/{y}.png`，Vite 将请求转发到地图服务器，不再读取 `map_xyz_9`。三维地图的 `/api/map1/{z}/{x}/{y}.png` 同样转发。浏览器无需跨域访问地图服务器；本机仍须能连接地图服务。

服务器请求失败时不会回退到本地瓦片，方便排查地址、端口或地图覆盖范围问题。清空此配置并重启开发服务，可恢复原来的本地缓存模式。本地配置文件被 Git 忽略，不影响其他开发电脑。

此配置只用于本地开发，无需更新后端；生产部署的地图仍由服务器现有代理配置提供。使用其他 Vite mode 时，在对应 `.env.<mode>.local` 中配置。

## 当前现场 Nginx 配置

现场前端监听 `19921`，其 `/api` 请求转发到 `192.168.10.254:8099`。地图服务监听 `8099`，根目录为 `/dji/html/map_xyz_9/`（以 Nginx 配置为准，注意不是 `xyz_map_9`）。

本机 `env/.env.development.local` 已设置 `DEV_MAP_TILE_TARGET=http://192.168.10.254:8099`。例如本地 `/api/18/206473/112458.png` 会转发到 `http://192.168.10.254:8099/18/206473/112458.png`，对应服务器文件 `/dji/html/map_xyz_9/18/206473/112458.png`。需重启开发服务生效，现场连通性尚待验证。
