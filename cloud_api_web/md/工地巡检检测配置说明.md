# 工地巡检检测配置说明

更新日期：2026-10-29。本轮实现平台配置、保存和计划快照；不实现新的算法提交、结果报文整理、报告生成或红外测温计算。

## 操作入口

1. 施工区域页顶部 → **默认检测配置**：设置当前工作空间的默认规则。初始可见光12项全选，红外关闭。
2. 选择工作面 → **工作面检测配置**：选择继承默认规则，或为该工作面保存独立规则。
3. 区域航线列表 → **航点检测配置**：逐点继承工作面规则，或独立选择检测项。总体航线页先保存工作面绑定，再点击 **航点检测配置**；未绑定工作面的点不能配置。

优先级为 **航点独立配置 > 工作面独立配置 > 工作空间默认配置**。每一级覆盖的是整套规则；切换独立配置时以当前生效规则作为初始值。

入口展示：工作面配置位于右侧面板顶部的独立高亮卡片，展示当前工作面名称；每条区域航线内提供整行“航点检测配置”按钮，总体航线绑定信息下方提供独立检测规则栏。航线校验未通过时，按钮下方说明不可配置原因。此入口样式调整只需更新前端，不涉及新增后端或SQL。

施工区域页点击航线名称或卡片空白/说明区域，会加载该航线详情并在地图上显示黄色连线和编号航点。打开“航点检测配置”也会先选择并预览该航线；地图上方显示当前航线名称、航点数及“定位航线”按钮。解除关联等操作不触发选择，校验未通过的航线继续提示错误，不显示为可执行航线。

“全不选可见光 + 红外关闭”是明确不检测，与“恢复继承”不同。关闭检测不影响照片采集和原图归档。修改规则不会修改KMZ镜头设置，也不会让没有红外拍摄能力的航线产生红外照片。

## 红外配置

红外温度异常与可见光“火灾烟雾”独立开关。开启红外后必须填写高温阈值（℃），并设置高温区域最小像素数。阈值由现场需求确定，平台不预设报警温度。

输入校验范围为 -50～1000℃、1～10000000像素，仅用于拒绝无效输入，不代表设备测温量程或算法已支持该量程。本轮只保存条件，温度计算、热点筛选及后续传输仍待实现。

## 计划与历史任务

- 保存规则后，**之后新建的计划**会冻结最终配置；已有计划继续使用创建时的快照。需要使用新规则时请新建计划。
- 单区域和总体航线计划均保存逐航点生效规则、来源和文件版本；下发、历史任务及离线任务包沿用该快照，不读取接收端的当前规则覆盖历史。
- 航点独立规则按航线及文件签名隔离；替换KMZ后需重新检查和配置，不能直接沿用旧文件同号航点的规则。
- 历史任务没有配置快照时不补造。照片无法确认航点时，后续分析接入还需明确处理，不将工作面归属误当成航点归属。

## 平台配置接口与部署

执行后端 `sql/20261029_construction_analysis_config.sql` 创建 `construction_analysis_config`，然后构建部署前后端。仅更新前端无法保存配置。无需迁移已有任务数据。

`GET /api/construction/analysis-config` 与 `PUT /api/construction/analysis-config` 是平台内部配置接口，不是算法服务接口。工作空间从登录身份取值。

| 配置上下文 | 查询参数 |
| --- | --- |
| 默认 | 无 |
| 工作面 | `area_id` |
| 区域航线航点 | `area_id` + `wayline_id` |
| 总体航线航点 | `overall_id` |

保存包含 `target`（default/area/waypoint）、`expected_revision`、`policy`。航点还须传 `waypoint_index`、`file_sign`、`route_version`。恢复继承传 `policy: null`；默认层不能继承。版本冲突时重新加载，避免覆盖其他人的修改。

规则结构示例（仅平台保存结构，不是算法请求）：

```json
{
  "visible_checks": ["person_count", "fire_smoke"],
  "infrared": {
    "enabled": true,
    "max_temperature_c": 80,
    "min_hotspot_pixels": 10
  }
}
```

示例数值不是现场推荐值。关闭红外时温度允许为null；可见光检查项允许空数组。人数去重仍按原接口约定由算法侧负责，本轮不执行人数统计。
