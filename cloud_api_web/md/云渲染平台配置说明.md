# 云渲染平台配置（2026-11-13）

## 使用方式

在“变量管理 → 云渲染管理 → 室外渲染配置”修改：

- 启用开关立即保存到后端；保存失败会提示并恢复开关原值。
- 服务地址、点云文件、配准参数、TURN 参数通过“保存并重连”保存。
- “重新读取平台配置”读取最新配置并替换表单中尚未保存的内容。
- “恢复部署默认值”需要确认，之后将当前前端 `config.js` 的默认配置保存到后端，对整个平台生效。
- 各浏览器刷新或重新进入页面时读取平台配置；已打开的其他浏览器页面不实时推送更新。

配置按后端部署实例共享，不按账号、浏览器或工作空间分别保存。接口要求已登录的 Web 平台用户及有效工作空间；沿用当前平台用户权限模型，未新增管理员角色。退出登录和清除浏览器缓存不会删除后端设置。

## 初始化与持久化

后端第一次尚无配置时，首次已登录的前端访问使用 `config.js` 的 `cloudRenderer` 初始化。此前浏览器 `localStorage` 中的旧云渲染配置不再读取或自动迁移，避免某个旧浏览器覆盖平台统一设置。升级后请在页面确认并保存现场需要的开关状态。

保存后以后端为准；修改或重新发布 `config.js` 不会覆盖已保存配置。需要采用新的默认值时，在页面执行“恢复部署默认值”。

默认保存文件相对于 Java 启动目录：

```text
./data/platform/cloud-renderer.json
```

现场从 `/dji/java` 启动时，文件是 `/dji/java/data/platform/cloud-renderer.json`。重启、替换 JAR 或前端升级时保留此文件。文件包含 TURN 凭据，应随平台数据备份并限制访问，不放到前端公开目录。

可选后端配置（通常无需填写）：

```yaml
platform:
  cloud-renderer-config-file: /dji/java/data/platform/cloud-renderer.json
```

后端运行账号需要对此目录有写权限。采用文件锁、配置版本检查及原子替换保存；多人修改冲突时拒绝旧版本，页面需重新读取后再保存。配置文件损坏或接口请求失败时不自动恢复开启，页面会提示，地图暂时使用二维模式。

## 接口

`GET /api/platform/cloud-renderer-config` 返回 `configured`、`revision`，已配置时含 `config`。

`PUT /api/platform/cloud-renderer-config` 接收 `{ revision, config }`，版本不匹配返回 HTTP 409。首次初始化用 `revision: 0`。响应沿用平台 `{ code, message, data }` 包装。响应禁止缓存，配置请求不通过会打印响应内容的通用 HTTP 日志拦截器。

## 部署与验证

本次前后端需一起更新，无 SQL 迁移。先部署后端并成功重启，再更新前端并强制刷新。只升级前端、仍连接旧后端时接口不存在，页面会提示读取失败。

1. 关闭开关，确认出现保存成功提示。
2. 刷新、退出重登，在另一个浏览器登录，确认仍关闭。
3. 重启后端后重新进入页面，确认仍关闭。
4. 两个浏览器同时打开配置页，一端保存后，另一端保存旧表单应提示版本冲突。
5. 恢复默认值后刷新，确认恢复结果已保存。

自动验证：`node scripts/test-cloud-renderer-settings.cjs`；使用 JDK 17 按 Java 11 目标编译并运行 `scripts/check-cloud-renderer-settings-backend.ps1`。测试覆盖初始化、清除浏览器存储后重登、多浏览器读取、重建后端服务实例、版本冲突、配置校验、接口身份校验及文件损坏。真实现场云渲染流的连接需部署后验证。
