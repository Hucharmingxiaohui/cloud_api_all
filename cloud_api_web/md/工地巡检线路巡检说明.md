# 工地巡检线路巡检说明

更新：2026-11-16。

## 与现有区域的关系

施工区域继续使用原区域表、区域 ID、区域接口及多边形包含校验。线路几何使用 `construction_line`、`construction_line_version`，不会转成施工区域，不会修改或迁移已标注的区域数据。

线路在共享计划、航线关联、照片归属及检测配置中使用 `line:<线路ID>`；区域仍使用原 ID。共享关系表中的旧字段 `area_id` 和算法协议中的同名字段继续作为分组标识使用，因此无需修改既有关系表结构、回填数据或升级算法报文字段。线路对象快照额外带 `target_type=line`，名称显示“线路 · 原名称”，避免同名对象混淆。

本次没有连接或修改现场数据库，也没有下发飞行任务。代码验证不代表现场数据库、算法服务或飞行验收完成。

## 线路自己的巡检航线和计划

1. 进入“变量管理 → 施工区域”，切换“线路”，选择已保存线路。
2. 右侧“巡检航线”支持上传 KMZ、关联公共航线库中的已有航线、地图预览、重新校验及解除关联。公共航线文件保留，解除关联不会删除文件。新建航线可先在公共航线管理中完成，再回到线路关联；本次没有新增线形自动规划或修改区域二维编辑器。
3. 线路不做多边形包含校验，允许拍摄航点位于折线两侧；仍检查 KMZ 格式、坐标、航点数量、文件版本及所属工作空间。
4. “线路检测配置”设置整条线路的检测项目和红外规则；关联航线的“航点检测配置”设置逐点覆盖。优先级仍为航点、线路、平台默认。
5. 点击“巡检计划”，或进入“任务管理 → 工地巡检计划”，在当前机巢完全覆盖的对象列表中选择“线路 · 名称”。只有该线路已关联的有效航线可以建计划。
6. 单对象计划沿用当前平台的 WGS84 绝对高度航线要求，不修改上传文件的高度值。创建与下发线路计划时，后端分别核对线路全部折点和航线全部航点在机巢已保存覆盖范围内；机巢位置、范围或关联版本变化可使旧计划被阻止下发。
7. 保存计划不会执行；仍须由用户在计划列表点击下发。线路暂停、归档或版本变化后的旧计划不能绕过校验执行。

覆盖检查是基于机巢圆形范围的几何判断，不代表障碍物、禁飞区、实际续航或进场/返航路径检查。线路不会通过虚构缓冲多边形来冒充区域。

## 总体航线同时绑定区域和线路

进入“总体航线与计划”，选择机巢并上传或选择航线。在绑定对象列表中既可选择原施工区域，也可选择完全覆盖的线路。勾选拍摄航点后点击“绑定选中航点”。一条线路可以绑定多个航点，同一总体航线可以同时巡检多个区域和线路。

一个航点仍只能归属一个对象，重新绑定会替换该航点原归属，避免照片重复提交和人数重复统计。转场航点可以不绑定。区域继续支持按多边形位置预选；线路须人工选择对应拍摄航点，不把折线当作多边形预选。

总体航线原有唯一照片后缀、执行版准备、文件版本和机巢覆盖校验继续保留。

## 照片、分析与历史结果

继续使用“飞行任务 → 任务结果”入口，不生成第二份结果。新计划冻结线路/区域标识、名称、绑定关系及检测规则；旧计划和历史任务不自动采用新配置。

算法仍按一次飞行任务提交。`line:<ID>` 是独立分组标识；线路和区域分别返回单图人数与对象内去重人数，不跨对象自行相加为工地总人数。红外规则与结果沿用原本地测温流程。结果归属、离线任务包和报告复用冻结快照，不依赖事后把线路伪装成区域。
