# 工地巡检本地红外测温

更新日期：2026-11-04。

## 流程与范围

工地任务继续使用原有“分析与结果”入口。按执行时冻结的三级配置，启用测温的红外照片由平台本机调用大疆 `dji_irp`，可见光照片仍提交站内分析服务；二者属于同一批次，返回进度包含本地与远端处理数量。纯红外任务不要求配置或连接远端算法服务。

点击“检查分析能力”会根据当前任务检查所需能力：红外检查本地SDK启用状态和文件执行权限，可见光检查远端服务。该检查不等同于真实照片解析成功；具体机型、动态库、照片支持情况在执行时验证。

红外关闭的照片继续保留原图，不做测温。后续修改区域或航点配置不改变历史任务快照；需要改变规则时新建相应巡检任务。已有历史批次不会自动补算，重新分析产生新批次。

## 部署

需要同时更新前后端，无SQL迁移。新测温功能默认关闭，在部署端已有配置中合并以下项目，避免重复声明已有的 `construction` 节点：

```yaml
construction:
  thermal:
    enabled: true
    executable: /dji/KmzKml/dji_thermal_sdk_v1.6_20240927/utility/bin/linux/release_x64/dji_irp
    library-path: /dji/KmzKml/dji_thermal_sdk_v1.6_20240927/tsdk-core/lib/linux/release_x64:/usr/local/lib64
    timeout-seconds: 60
```

路径只是与当前项目旧部署目录一致的示例，必须改为笔记本实际安装位置。使用与Linux系统架构和现场机型匹配的SDK及动态库，并授予后端运行用户执行权限。这里直接在本机运行，不使用旧测温功能的SSH配置。

旧的 `TemMeasureServiceImpl` 和点/区域测温接口没有修改。新流程在独立队列中处理，一个平台端的本地测温串行调用；每张照片创建系统临时目录 `construction-thermal-*`，原图副本、measure.raw、日志各自独立，处理完成后只删除本次目录内的已知文件。源照片不修改、不删除。进程超时会终止；强制断电/终止JVM可能留下系统临时目录，不会作为下一次测温输入。

## 温度与热点定义

- 复用现有SDK命令：`dji_irp -s 原始照片 -a measure -o measure.raw`。输入为归档的原始R-JPEG字节，不能使用截图或重新压缩的普通图片代替。
- 读取SDK输出中的 `image width` / `image height`，按现有SDK默认的有符号int16、小端序、0.1℃解析温度矩阵。强制验证字节数恰好为宽×高×2；不猜测或固定成640×512。无法获取尺寸或格式不匹配即失败。
- 使用冻结配置中的 `max_temperature_c` 作为高温阈值，温度大于等于阈值的像素按四邻域合并，单个连通区域像素数大于等于 `min_hotspot_pixels` 才计入热点。
- 保存全图最高、最低、平均温度，最高温坐标，热点数量、每个热点的矩形范围/像素数/最高温和判定阈值。最高温像素可能没有达到最小热点面积，此时有高温峰值但无符合配置的热点。
- 生成与温度矩阵同尺寸的热力图，白框标出符合条件的热点。颜色按本张图最低至最高温映射，不宜根据跨图颜色深浅比较绝对温度；以数值为准。
- 当前复用SDK默认测温参数，未新增发射率、反射温度、距离等校正参数配置；实际精度与SDK支持、采集条件及测温参数有关。温度异常不直接等同于火灾。

## 结果、失败与报告

逐图结果的 `infrared_temperature` 保存本地测温状态与结构化数据，既有结果图接口返回本批次热力图。温度数值、热点和证据图进入原有Word报告，不要求外部算法V1.0增加测温字段。

SDK缺失、不支持照片、超时、输出尺寸错误等返回明确失败，该图为PARTIAL，不显示为正常。纯红外处理结束后批次可以标记已完成，但逐图失败仍保留；混合批次同时等待远端结果。只做红外的工作面人数状态为not_requested，不伪造人数为0。

重复使用相同请求标识不重复分析。纯本地批次在服务重启时若未完成，标记失败并允许人工重新分析；混合任务中断且远端接收情况不明确时，沿用原有UNKNOWN状态，不自动重复提交。

## 验证及现场验收

Java 11定向编译和已有工地回归通过。新增测试覆盖阈值边界、连通热点、孤立高温像素、原图不变、温度矩阵尺寸读取、临时目录独立及清理、SDK失败、纯本地不发远端请求、混合批次进度/区域统计、请求幂等、证据图和Word报告。SDK进程使用模拟实现，尚未在本机真实运行Linux SDK。

前端组件编译、ESLint及浏览器模拟接口验证通过，包含最高温显示、热点阈值和“本地测温热力图”标识；其他任务的测温源码未改动，但旧功能仍需部署后用真实照片回归。

现场先用同一张原始红外照片分别执行旧点/区域测温和新本地分析，核对SDK读取尺寸、最高温位置、温度数值及阈值判定，再验证固定端/移动端的本地任务与离线导入任务。当前不把模拟测试当作真实SDK/设备验收。
