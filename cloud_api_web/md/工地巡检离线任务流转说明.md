# 工地巡检离线任务流转

更新日期：2026-10-28。

固定机巢端与移动机巢端使用同一套前后端代码，均可独立采集、导出、接收及回站手动分析。没有“只有移动端才能分析”的程序限制。以下以固定端采集、移动端接收为例，反向使用同样成立。

## 操作流程

1. 固定端完成一次工地巡检飞行，等待照片全部回传。
2. 进入该飞行任务的工地结果页，点击 **导出离线任务包**。程序先归档原图，再生成ZIP；页面显示完整本地路径。仅支持已完成且照片收齐、具有工作面执行快照的任务。
3. 移动端打开 **任务管理 → 飞行任务**，在“离线接收 · 工地巡检结果”中展开“拷贝目录与使用方法”，查看当前工作空间的实际接收目录。
4. 将ZIP通过U盘或现场网络拷到接收目录。复制过程中使用 `.part` 后缀，复制完成后改为 `.zip`；也可以先复制到目录外，完成后再移入接收目录。不要把正在写入的ZIP交给接收操作。
5. 点击 **刷新并接收**，也可点击飞行任务页上方“查询”一起刷新。页面显示每个包的成功、跳过或失败原因。正常打开页面只读取接收列表，不自动扫描目录。
6. 成功的任务出现在同一飞行任务页面的“离线接收”列表，带来源机巢、来源部署编号、执行时间和原图数量。点击 **查看任务结果**，打开已有工地巡检结果页。
7. 回站后连接分析主机，从对应任务结果中手动分析。两台设备不同时刻的飞行仍是不同任务，不能把不同任务的人数合并去重。

导入任务不出现在可执行航线计划中，不支持续飞、重下发或控制来源机巢。它是已经发生的飞行的离线结果记录。普通飞行任务列表及操作保留，接收结果在同页独立分组、检索和分页，不混用飞行计划的删除/下发接口。

## 数据包包含什么

```text
inspection-任务来源标识-版本摘要.zip
├── manifest.json
└── originals/
    ├── 照片标识.jpg
    └── 照片标识.dng
```

为便于完整校验，任务、来源、快照、照片清单及人工归属统一收在一个 `manifest.json`，不要求用户手动维护多个JSON。

| 字段 | 内容 |
|---|---|
| `version` | 当前数据包格式版本1 |
| `origin` | 来源部署编号、来源工作空间、原飞行任务ID |
| `task` | 原任务名称、执行时间、结束时间、机巢、状态、照片数量等记录 |
| `snapshot` | 本次执行冻结的工作面、航点、照片后缀及已有配置 |
| `photos` | 每张原图的ID、原文件名、包内路径、镜头子类型/机型载荷信息（源记录存在时）、字节数和完整性摘要 |
| `associations` | 已有人工工作面归属、排除原因、操作人/时间及决策版本 |

原图按原始字节传输，保留图片扩展名，不压缩转码、不重命名原记录中的文件名。摘要用于离线包内部损坏检测，与算法接口协议无关，不要求算法增加校验码字段。

本版不携带数据库文件、账号、设备绑定、可执行计划、`.lock`、正在运行的分析请求或已生成的算法报告。接收后在本机产生新的分析批次。已接收任务再次导出时，保留最初来源，并携带当前人工归属。

### 工作面与历史快照

- 总体航线使用执行时的多工作面航点绑定；新增总体绑定会同时冻结工作面边界。
- 单区域任务使用执行快照中的工作面，全部照片保留该工作面归属，不依赖另一台平台存在同名区域。
- 工作面ID只在来源任务快照内解释，不插入或覆盖本机施工区域、航线或机巢配置。
- 旧总体任务快照若没有边界，保留原有绑定信息，不拿当前边界冒充历史边界。完全缺少工作面执行快照的任务会拒绝导出，并说明原因。
- 现阶段检测项多级配置和Base64算法客户端仍待开发。本功能保留已有快照，不能将尚未实现的检测配置视为已经携带或启用。

## 本地目录与配置

建议Linux部署时使用固定绝对路径，例如：

```yaml
construction:
  storage-root: /data/construction
  transfer-root: /data/construction-transfer
  transfer-max-bytes: 10737418240
```

目录需允许后端运行用户读写。未配置时默认相对后端工作目录的 `./data/construction` 和 `./data/construction-transfer`；界面显示解析后的绝对路径。

```text
construction-transfer/
├── deployment.id                     本部署稳定编号
└── 工作空间派生编号/
    ├── inbox/                        等待接收的.zip；忽略.part
    ├── imported/                     已处理包和接收回执
    ├── failed/                       失败包及原因回执
    ├── exports/                      本机生成的离线包
    └── scan.lock                     防止并发扫描

construction/
└── 本机工作空间派生编号/
    └── 本机任务派生编号/
        ├── transfer.json             离线来源、任务、快照及导入记录
        ├── media.json                原图归档清单
        ├── associations.json         本机人工归属记录
        ├── 照片标识.jpg              实际原图
        └── ...                       本机后续分析批次等
```

两台电脑应独立生成各自的 `deployment.id`。复制程序代码时不复制对方的数据目录或部署编号；同一台电脑升级或恢复时则保留自己的编号，避免后续来源变化。数据备份需要同时覆盖原图目录、接收/导出目录及部署编号。

不需要手工插入数据库。导入结果由当前工作空间下的本地记录登记，只有整包验证和落盘成功后，才通过原子目录发布进入列表。任务详情、照片预览、人工归属和分析提交复用原有工地接口。

默认单包原图总大小上限10GiB，清单上限16MiB，照片最多20000张；一次扫描最多100个ZIP。超限应调整双方容量或按不同飞行任务分别导出，不能把一次飞行随意拆成多个独立分析任务。

## 重复、冲突与失败处理

- 以“来源部署编号＋来源工作空间＋原任务ID”识别同一任务，在本机生成稳定的 `offline-...` 任务ID。
- 相同包重复接收：跳过，保留已有人工归属和分析结果。
- 同一来源任务内容不同：拒绝覆盖，移到失败目录并提示核对；本版不提供自动合并或强制覆盖。
- 本部署自己的来源任务：先按来源工作空间与原任务 ID 查询原任务记录。原任务仍存在时跳过，不生成第二份结果；即使计划已删除或图片缺失，也不把仍存在的任务当成已删除。
- 原任务记录已删除时，允许导入本部署导出的包；仍完整校验原图和清单，并以稳定的 `offline-...` ID 恢复到“离线接收”列表。恢复照片、任务快照和包内人工归属，不重建可执行计划或原飞行任务数据库记录。分析批次和报告不在此包内，恢复后需重新分析。
- 恢复后重复导入仍按离线任务记录去重，保留本机后续人工修改及分析；包内容不同则拒绝覆盖。数据库查询失败时接收失败，不按“原任务不存在”处理。
- 缺原图、照片损坏、清单数量不符、非法路径、重复文件、未知格式：接收失败，任务不会部分出现在列表。
- 接收失败后可根据回执重新导出/拷贝，再将修复包放回 `inbox`。
- 已导入记录不自动补下载来源端照片；本地文件后来丢失或损坏时，应恢复本机备份。重复包不会覆盖本机当前分析数据。
- 移入回执目录失败时，页面提示；下次扫描仍通过任务标识去重，不重复创建。

## 接口与部署

### 单平台验证本机任务恢复（2026-11-13）

1. 选择可删除的测试任务，确认照片收齐，导出离线任务包并在数据目录之外另存一份。
2. 原任务尚在时，将包放入当前工作空间 `inbox`，点击“刷新并接收”：应提示原任务仍存在并跳过。
3. 通过平台删除该测试任务结果，确认任务记录已删除。仅删除照片文件不属于此恢复场景。
4. 将备份包再次拷入 `inbox`，点击“刷新并接收”：应提示“本机原任务已删除，已恢复为离线接收结果”。
5. 在“离线接收”中查看照片和工作面归属；需要分析时重新提交。再次拷入同一个包，应跳过且只保留一份离线结果。

此功能需更新并重启后端，无数据库迁移，也无需更改部署编号。不要为测试修改或删除 `deployment.id`。

所有接口使用当前登录工作空间权限，不接受客户端指定导入目标工作空间。

| 接口 | 功能 |
|---|---|
| `POST /api/construction/tasks/{jobId}/export` | 在后端本地生成任务包，返回文件名和绝对路径 |
| `GET /api/construction/transfers` | 当前工作空间的目录、部署编号及离线接收任务列表 |
| `POST /api/construction/transfers/scan` | 扫描当前工作空间inbox并返回列表及逐包回执 |
| 现有 `/api/construction/tasks/{jobId}` 相关接口 | 导入任务的详情、原图、人工归属及本机分析 |

本次需要部署前端和后端，无新增SQL。已有工地巡检表和此前迁移仍需正常部署。不能仅复制前端就使用接收功能。
