# 厂家 JSON 航线转换（机场 3 / M4TD）

入口：**航线管理 → 航线转换**。本期转换在浏览器本地完成，不上传 JSON，不自动导入航线库，不创建或下发任务。

## 操作

1. 选择不超过 20 MB、包含 `points` 执行航点的厂家 JSON。只有设备标定点的工程文件不可转换。
2. 核对航线名称、航点/拍照数量、经纬度与高度范围。源 `cameraType=41/44` 不等同于 DJI 镜头定义。
3. 根据原拍摄用途，显式选择 M4TD 广角、红外或“可见光＋红外”。双光以同一拍摄动作保存两种通道图像，不生成融合图；航点和拍摄姿态不变。本期支持原倍率 1、单次拍摄，不推断焦距或支持未知变焦。
4. 显式选择结束动作，并复核安全起飞高度、全局返航高度。自动降落不等于返回机场，不应误选。
5. 阅读并确认高程、镜头与停点动作转换假设，点击“转换”。
6. 分别下载 KMZ 和转换报告。报告保留航点、原目标 ID/名称、拍照后缀、源相机类型、输出镜头及高度换算结果；空名称保留为空并告警。`expectedImageCount` 为按镜头数估算的图像数，双光为拍摄动作数的两倍，不是实机采集结果。
7. 确认文件及现场条件后，再通过既有“导入航线”入口导入 KMZ。导入成功、机场接受任务、实际正确执行是不同的验证层次。

## 高程

- 原 `height/dh` 按 **WGS84 椭球高**解释，这是当前源文件分析支持的假设，不是厂家已确认的测量结论。
- `waylines.wpml` 使用 `executeHeightMode=WGS84`，保持原执行高度。
- `template.kml` 使用 EGM96 模板高度模式，同时写入原椭球高 `ellipsoidHeight=h` 与 `height=H=h-N`。
- N 来自部署在 `public/geoid/us_nga_egm96_15.tif` 的全球 NGA EGM96 15′ 模型，按需本地加载并校验 SHA-256；不是地面 DEM，也不改变原航点离地高度。
- 模型缺失、损坏或不匹配会阻止转换，不使用零偏移或约 12 米的常量替代。静态部署必须包含 `geoid/` 目录。来源、公共领域许可与精度说明见 `public/geoid/README.md`。

## 动作与限制

- 固定输出 M4TD：飞机枚举 100/1，负载枚举 99，挂载位置 0。没有通用机型切换。
- 飞行按逐点停稳模式输出；先执行机头/云台姿态，再按源 `yawPitchArray` 顺序拍照。没有拍照配置的点不会自动拍照。
- 对源结束枚举不作返航含义猜测，采用用户选择；源转弯模式仅接受已调查值，仍明确提示输出停点语义。
- 本期最多 2000 航点、每点 10 组拍摄、总拍摄 4000 次；这些是转换器限制，不是设备执行或续航保证。
- 云台俯仰范围按本期 M4TD WPML 支持的 -90° 至 +30° 校验；不截断不支持的角度。
- 转换 KMZ 保留正俯仰角。现有云渲染三维编辑器的回读映射会将正角度截为 0°，因此含仰拍的航线不要经该编辑器重存；本次未修改该既有编辑器行为。
- 无安全围栏转换、不自动规避障碍、不生成设备目标点对应的全新航线、不拆分近千点航线。
- 输出支持统一的广角、红外或广角＋红外（WPML 镜头值 `wide,ir`，模板和拍照动作同步）。源文件混用多个厂家相机类型仍需先明确逐动作映射；未知拍摄字段、未知相机类型、非倍率 1 或非单次拍摄等不能静默降级。
- 安全起飞/返航参数需要现场确认；本工具未进行实机验证，文件生成不代表安全可飞。

```text
node scripts/test-vendor-json-kmz.cjs
```
