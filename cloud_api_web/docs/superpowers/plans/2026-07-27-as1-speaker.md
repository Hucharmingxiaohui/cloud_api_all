# AS1 Speaker Control Implementation Plan

## Goal

Add DJI AS1 TTS speaker control to the lower-right `/remoteDebug` console. Reuse the existing DRC MQTT session and support dynamic AS1 discovery, TTS settings, single/loop playback, stop, replay, progress, and DJI error feedback.

## File Map

- Modify `src/components/g-map/use-mqtt.ts`: own the single DRC subscription/heartbeat, dispatch every valid DRC message, and expose a shared publisher type.
- Modify `src/components/g-map/use-manual-control.ts`: accept the shared publisher instead of creating a second `useMqtt()` lifecycle.
- Modify `src/types/drc.ts`: add Dock 3 AS1 DRC method constants.
- Add `src/components/devices/speaker/as1-speaker.ts`: protocol types, state normalization, command builders, MD5, and error descriptions.
- Add `src/components/devices/speaker/use-as1-speaker.ts`: AS1 state machine and command sequencing over the shared DRC transport.
- Add `src/components/devices/speaker/As1SpeakerPanel.vue`: focused lower-right TTS controls and status UI.
- Modify `src/components/devices/drone_control/drone-control.vue`: mount the panel and pass the shared transport/DRC state.
- Add `scripts/test-as1-speaker.cjs`: dependency-free behavior tests for command payloads, discovery, progress, and MD5.

## Tasks

1. Add failing protocol tests for UTF-8 MD5, dynamic `psdk_index`, command payloads, state/progress normalization, and DJI error mapping.
2. Implement the pure speaker protocol module until the tests pass.
3. Refactor manual control to consume the existing `useMqtt()` publisher and fix duplicate heartbeat/subscription ownership.
4. Expand DRC message dispatch so AS1 state, progress, and command replies reach the speaker state hook.
5. Implement `useAs1Speaker` with monotonic command `seq`, initial state subscription, ordered TTS configuration, play/stop/replay, pending response tracking, and reset on DRC exit.
6. Implement `As1SpeakerPanel` with text validation, voice/language/volume/speed/mode controls, visible playback progress, and persistent stop action.
7. Integrate the panel below the existing flight/load controls in the `/remoteDebug` right-side console without adding another route or MQTT client.
8. Run the speaker behavior tests and production build; review the resulting diff for duplicate DRC lifecycle creation and unsafe hard-coded PSDK indexes.

## Acceptance Criteria

- Only one `useMqtt(deviceTopicInfo)` call exists in `drone-control.vue`; `useManualControl` does not call it.
- The speaker panel remains disabled until DRC topics are available and an AS1 `Speaker` state supplies `psdk_index`.
- Every command uses the discovered `psdk_index`; no production command hard-codes `2`.
- Playback sends TTS settings, play mode, then TTS text with a deterministic lowercase UTF-8 MD5 and increasing `seq` values.
- UI distinguishes command acceptance from processing/playback completion and shows `drc_speaker_play_progress` state.
- Stop remains available while transferring, converting, downloading, or playing.
- Tests and `npm run build` pass.
